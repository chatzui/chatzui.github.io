Section Config

Section configs are the source of truth for how a domain’s data is fetched and displayed. They live in src/sections/<domain>/ and are imported by Astro pages.

Location

src/
└── sections/
    ├── shop/
    │   ├── config.js       # Product section configs
    │   └── featured.js     # Featured items section config
    ├── blog/
    │   └── config.js
    └── home/
        └── config.js

Each domain has its own subdirectory. A domain can have multiple config files — one per logical section.

Config Keys

A complete section config object:

{
  id: 'shop-products',          // string — unique id, used as conductor section key and cacheKey
  title: 'Products',            // string — display title (optional)
  dataApi: '/api/products.json',// string — API endpoint for Conductor to fetch
  cacheKey: 'shop-products',    // string — IndexedDB cache key
  cacheTtl: 300,                // number — cache lifetime in seconds
  config: { /* baseConfig */ }, // object — layout and cell config for web-boxs
  anime: 'fade-up',             // string — entrance animation class (optional)
}

Key Reference

KeyTypeRequiredDescription
idstringYesUnique identifier. Must match the conductor section key.
titlestringNoHuman-readable title for the section.
dataApistringNoURL Conductor fetches data from.
cacheKeystringNoIndexedDB key for caching responses. Omit to disable cache.
cacheTtlnumberNoCache lifetime in seconds. 0 or omitted = no TTL.
configobjectYesThe baseConfig object passed to web-boxs.
animestringNoEntrance animation class for cards.

Full Example

// src/sections/shop/config.js

export const productConfig = {
  id: 'shop-products',
  title: 'Our Products',
  dataApi: '/api/products.json',
  cacheKey: 'shop-products',
  cacheTtl: 300,
  anime: 'fade-up',
  config: {
    tiers: [
      { cols: 1, minWidth: 0 },
      { cols: 2, minWidth: 640 },
      { cols: 4, minWidth: 1024 },
    ],
    makes: [
      { opt: 'image', val: 'thumbnail', stys: { aspectRatio: '4/3' } },
      { opt: 'text',  val: 'name',      stys: { fontWeight: '600' } },
      { opt: 'price', val: 'price',     stys: { color: 'var(--color-primary)' } },
    ],
    groupStyle: {
      background: 'var(--color-base-100)',
      borderRadius: 'var(--radius-box)',
    },
  },
};

export const featuredConfig = {
  id: 'shop-featured',
  title: 'Featured',
  dataApi: '/api/featured.json',
  cacheKey: 'shop-featured',
  cacheTtl: 600,
  config: {
    tiers: [{ cols: 1, minWidth: 0 }, { cols: 3, minWidth: 1024 }],
    makes: [
      { opt: 'image', val: 'image', stys: { aspectRatio: '16/9' } },
      { opt: 'text',  val: 'title' },
    ],
  },
};

Import Pattern

Import the config in an Astro page and pass it as a serialized prop:

---
// src/pages/shop.astro
import Layout from '@/layouts/Layout.astro';
import { productConfig } from '@/sections/shop/config.js';
---

<Layout title="Shop">
  <web-boxs
    config={JSON.stringify(productConfig.config)}
    dataApi={productConfig.dataApi}
    cacheKey={productConfig.cacheKey}
    cacheTtl={String(productConfig.cacheTtl)}
    ui="modern"
  ></web-boxs>

  <script type="module" src="/src/webs/apex/web-boxs.js"></script>
</Layout>

Or pass the entire config to web-board as a sections array:

---
import { productConfig, featuredConfig } from '@/sections/shop/config.js';
const sections = [featuredConfig, productConfig];
---

<web-board sections={JSON.stringify(sections)} ui="modern"></web-board>

Grouping Multiple Configs

For domains with many sections, export all from a single index.js:

// src/sections/shop/index.js
export { productConfig }  from './config.js';
export { featuredConfig } from './featured.js';
export { saleConfig }     from './sale.js';

Then import cleanly:

import { productConfig, featuredConfig } from '@/sections/shop/index.js';

Color Rule Reminder

All sty values inside config.makes and config.groupStyle must use CSS variables only:

// Correct
{ stys: { color: 'var(--color-primary)' } }

// Wrong
{ stys: { color: '#3b82f6' } }
